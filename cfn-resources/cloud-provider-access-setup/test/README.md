## MongoDB::Atlas::CloudProviderAccessSetup

### Impact
The following components use this resource and are potentially impacted by any changes. They should also be validated to ensure the changes do not cause a regression.
- CloudProviderAccessSetup L1 CDK constructor
- `MongoDB::Atlas::CloudProviderAccessAuthorization` (the paired resource that authorizes the role ARN)
- `MongoDB::Atlas::EncryptionAtRest` (uses the returned role id)

### Resources (and parameters for local tests) needed to manually QA:
An existing Atlas project is required. The test input generator creates one.

## Manual QA:

### Prerequisite steps:
1. Follow the general [prerequisites](../../../TESTING.md#prerequisites) for testing CFN resources.

### Steps to test:
1. Follow the general [steps](../../../TESTING.md#steps) to test CFN resources.
2. Run the contract tests with `make create-test-resources`, `make run-contract-testing`, and `make delete-test-resources`.

### Success criteria when testing the resource
1. Create registers a new Cloud Provider Access role in the project and returns `RoleId`, `AtlasAWSAccountArn`,
   `AtlasAssumedRoleExternalId`, `CreatedDate`, and `FeatureUsages`.
2. The role appears in the project's Cloud Provider Access roles in the Atlas UI.
3. Delete removes the whole role registration. Deleting an already removed registration returns `NotFound`.
4. Deleting a role that a feature still uses, for example Encryption at Rest, fails with a clear message.
5. General [CFN resource success criteria](../../../TESTING.md#success-criteria-when-testing-the-resource) should be satisfied.
6. Create first returns `IN_PROGRESS` with the registered role, and the callback context carries that
   `RoleId`. The callback returns `SUCCESS` for the same role. Repeating the callback must not add another
   registration. A callback for a missing role must fail with `NotFound` and retain the role id, rather than
   register a replacement.

The unit tests exercise the create checkpoint, the callback context, and repeated callbacks with a fake HTTP
transport. They do not cover recovery after a create response is lost before the role id is checkpointed; see
the [create retry limitation](../README.md#create-retries).

## Local Testing

The local tests are integrated with the AWS `sam local` and `cfn invoke` tooling features:

```
sam local start-lambda --skip-pull-image
```
then in another shell:
```bash
repo_root=$(git rev-parse --show-toplevel)
source <(${repo_root}/quickstart-mongodb-atlas/scripts/export-mongocli-config.py)
cd ${repo_root}/cfn-resources/cloud-provider-access-setup
./test/cloudprovideraccesssetup.create-sample-cfn-request.sh YourProjectId > test.request.json
echo "Sample request:"
cat test.request.json
cfn invoke CREATE test.request.json
```

`RoleId` is generated by the create, so add it to the request before deleting:

```bash
jq --arg roleId "<RoleId from the CREATE response>" \
	'.desiredResourceState.RoleId?|=$roleId' test.request.json > test.delete.request.json
cfn invoke DELETE test.delete.request.json
```

Both CREATE and DELETE tests must pass.
